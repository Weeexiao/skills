# POV 生成与验收

仅在用户要求实际制作、继续出片或修正生成问题时读取。来自庞贝短片的可迁移经验；不把当时的供应商、音色、时长和人数固定成其他项目默认值。

## 接手已有项目

先读剧本、真实素材、音频、视频节点/历史和供应商任务记录，确认最新用户修改。区分不同镜号与同镜多版。保留已采用片段及未提交改动，只新增当前修订需要的节点和文件。

项目记录至少能回答：镜号/版本、引用资产、实际旁白、授权状态、请求ID、上游任务ID、生成状态、输出文件、检查方式、采用/拒绝原因及实际费用。使用现有结构，不为每次任务另造一套应用。

连接失败先检查正确服务和项目页面。多个页面打开同一画布可能导致版本冲突；先保存用户编辑、识别重复页面并重新加载最新内容，不绕过版本检查或关闭鉴权，也不启动一个旧构建假装恢复成功。激活画布通过应用已有工具改，不能直接写画布JSON抢覆盖。

## 资产和空间先于提示词堆叠

按实际需要准备手部、场景、互动人物、关键道具和旁白，标明外观、衣服、左右手锚点。新增资产与旧版并存。

空间账本记录世界位置，而不只记画面左右。例如门的铰链在哪、向内还是向外开、从室内看把手在哪、邻居抓哪只手、镜头是否已通过门槛。换朝向后屏幕左右可变，物体归属不能变。

同一邻居不能在相邻镜换脸换衣。若实际采用的分镜已经定义了新外观，下一镜绑定已采用外观，不再绑不一致的早期角色图。

关键道具反复被忽略时，把它放进参考图，写明持有人及朝向。本次文字里的“短暂举手机”曾只表现成抬手；加入游客双手持手机、后置镜头朝向观众的单幅参考后，举起、取景和放下更清楚。不能把游客的手写成视点主人的手。

## 参考形式怎么选

| 需求 | 起始选择 | 必须检查 |
|---|---|---|
| 简单同机位、一个完整动作 | 一张全幅参考图 | 关键道具真正在图里，人物及动作归属明确 |
| 多步连续行动、构图变化较多 | 多宫格分镜参考 | 格间空间连续，逐格扩为全屏，不带格线 |
| 接续上一段动作 | 上一段实际尾帧，辅以必要外观参考 | 是参考引导还是首帧锁定，不能混称 |
| 验证路径/站位/运动 | 可选白模预演 | 先过速度、慌张反应、落脚起伏与转头落点 |

四宫格可用A左上、B右上、C左下、D右下声明顺序，每格成为一个时间段的完整画面；不是四张图同时显示，也不是四个视频窗。按当前模型规范声明引用，不因提示词里写了“参考二”就认为第二张图已被使用。

本次浮石、抓腕入屋和灰流段的四宫格推动了动作，展陈段却出现上下复制。换成单幅后仍有横框分隔，说明“只换单幅”不够。移除展柜横框、重复反射和边界，再用连续天花板贯穿全画面，才取得无分屏候选。这是本次修正路径，不能断言所有横框都会导致分屏。

遇到分屏/黑边/重复：先看真实成片并准确分类；检查拼图、横框、镜面、黑带和争夺完整构图的参考；简化为干净全幅图，保留必要身份/道具；复核图片后再提交授权内的修订。不仅追加禁止词，也不以裁掉半屏冒充修复成功。

第二张图“已连接”不等于“用上了”。给各图单独职责，出片后核对可辨识特征；重复、冲突或无必要的参考可以移除。

## 运镜、表演与关键动作

按“触发—运动—落点”写运镜，急转后停稳。庞贝片以约0.25—0.35秒完成急转作为起始调参，仅是当时创作选择，不要求所有动作同速。行走由落脚推动短促起伏，近墙向后掠过证明视点在移动；不匀速漂浮，也不全程抖得看不清。固定展陈视点可以完全不动，外面的人在动。

群众安排近、中、远反应。例如近处缩身护头、中景丢篮转向、远景奔向不同出口；不全员同步，也不堵死视点路线。人数和反应强度按题材、画幅与现有画面调整。

关键动作要能被观众认出。游客拍照可写：

1. 游客持一部手机，手腕接到自己的衣袖；视点主人不出手。
2. 举起并调整方向，后置镜头指向观众，屏幕朝游客眼睛。
3. 稳定取景，完成一次拍照触发动作，再放下，不能写成“想拍又放弃”。
4. 道具完整可见，不同时挡住两人的脸。若实际自然转为横持，可按用户目标判断，不把提示词逐字一致当唯一标准。

给主动作足够时长，不在一个短片段塞过多动作。音效辅助动作，不能靠快门声掩盖画面里没有手机。

## 固定旁白与声音

取得用户采用的真实音色/录音，记录来源、文件和使用范围；需要复用时登记音频资产，不只保存文字形容。

加快语速优先对已确认录音做保音高处理，逐段检查字句、停顿和时长，不让每段随机生成“类似男声”。引擎支持原音频复用时才绑定实际录音并按当前模型规范声明用途；标签校验通过不证明波形已保留。用户仅采用了音色，不等于采用画面。

旁白主导信息，呼吸/脚步/落石表达身体和空间，BGM是可选层，不自动每段加音乐。用户后来要BGM时再选曲并核对来源与许可。本次黑场停乐、展陈保留环境/拍照声是剪辑建议，不是所有POV的固定结尾。

## 收费提交与恢复

- 核对实际工作流及计费来源，沿用用户确认选项；不凭名字含H3、API或ComfyUI推断扣现金/RH币，应用可执行图与用户确认分别记录。
- 提交前完成引用、提示词和参数校验，并记录提交起点；返回后保存请求ID和上游任务ID。
- 小批量确认平台名额后继续，本次的并发上限不是平台永久配额。
- 连接中断、超时、提交状态不明时，先查原请求、节点、供应商台账和文件，不重复生成，不把本地超时当上游失败。
- 查询/恢复原任务与新收费重做是两种操作，仅调用实际可用的能力，不猜端口、工具名或字段。
- 费用空值照实记录，不据此声称退款、免费或只扣某币种；已有用户明确确认时沿用其确认范围。

## 分层验收与采用

| 检查 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 提示词/引用校验 | 语法和绑定通过 | 视角、空间或动作正确 |
| 任务成功、文件存在 | 有真实产出 | 可采用，或对应另一镜号 |
| 完整解码、尺寸/时长 | 编码和技术属性可读 | 表演、声音或叙事通过 |
| 抽帧 | 所抽时点的画面状态 | 已看完运动，已听过声音 |
| 连续播放/听验 | 实际检查到的运动/声音 | 用户已采用 |
| 用户明确采用 | 可选用的实际版本 | 以后每个新版自动采用 |

逐项检查主角是否变成画内背影、肩/脸入镜、慢摇、人群只站着、动作省略、分屏/重复、门与人物连续性、旁白完整及音色。关键动作加密检查，发现问题如实命名，不把“两宫格”淡化成黑边。没有听验不能报告已听验。

明确原因后定向修正一次；仍失败或原因不清时保留候选、说明限制并让用户选择下一步，不连续付费抽卡。收费重试始终受当前授权范围约束。

区分候选、拒绝、已检查、待采用、已采用。多个成功文件可能只是同镜修订，不能按成功总数宣布不同镜头都完成。用户否决版本标清原因但保留；已采用片段不随别段重跑。仅视频导出读取明确采用记录，不按最新版、当前下拉项或修改时间自动挑选。选择功能不存在时交付清晰文件清单，不假称已开发或已设置。

## 用量实验与后续发布

庞贝项目的DSH曾做白模，后来用户因慢及缺乏慌张反应而弃用，不能只凭完成报告宣布节省成功。没有同任务、同质量、同验收条件的Codex独立执行基线，就不能给节省百分比。生成等待时间、RH币、DSH token和Codex额度分开报告，缓存也不等于替代了等量Codex消耗。

封面和发布文案仅在用户提出时制作，分别排版指定比例并检查文件真实尺寸、中文文字、POV边界和安全边距。情境演绎明确其性质，不把虚构人的死亡体验包装成已证实史实。音乐推荐与实际混音/外部发布分开；推荐一首歌不构成自动换轨或公开发布的授权。
