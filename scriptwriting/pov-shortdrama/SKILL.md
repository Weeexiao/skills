# POV 第一人称「成功人生」短剧剧本生成器

一句话：**用户丢一个主题 → 你问 3-4 个问题 → 直接产出 Toonflow 格式的完整 POV 分场剧本。**

主线固定为爽点曲线：**被轻视 → 伏笔 → 反转 → 全场崇拜/有求于你 → 高光加冕定格**。

## 何时触发

- 用户给出「XX POV」「第一人称视角」+ 成功/逆袭/爽文类主题
- 用户提到：POV、第一人称、代入感、爽文短剧、逆袭、全场跪拜、领奖、捧杯、加冕、体验不同人生
- 用户要求做「成功人生」题材的 AI 短视频脚本

## 工作流

### 第 1 步 · 锁定题材

从用户输入提取「身份/职业 + 世界观」。读 `references/genre-library.md`：

- **命中已有题材卡** → 直接取用它的角色卡、术语库、默认高光时刻作为问答的默认值。
- **未命中** → 按该文件末尾的「题材卡模板」现场推导一张卡再用。

### 第 2 步 · 问答确认（默认必须做）

用**当前环境自带的提问工具**「一次性」抛出 3-4 题，不要一问一答来回消耗用户耐心。工具名按运行环境选：DSH 用 `ask_user_question`（参数 `questions: [{ id, question, header, options: [{ label, description }], multi_select }]`，选项文字写在 `label` 里）；Codex 用 `AskUserQuestion`。四要素：

| # | 要素 | 作用 |
|---|------|------|
| 1 | 世界观 / 设定细化 | 定基调（古典仙侠 vs 现代修真；世界杯国家队 vs 俱乐部欧冠） |
| 2 | 主角起点与被轻视的场景 | 定反差强度——越具体越爽 |
| 3 | 高光时刻形态 | 定全片落点（领奖 / 加冕 / 捧杯 / 揭身份 / 万人跪拜） |
| 4 | 篇幅与结尾处理 | 定场数与镜头量、是否留钩子 |

硬性要求：

- 每题 2-4 个选项，推荐项放第一位，并在 `label` 末尾标注「（推荐）」。
- 选项必须**具体、有画面感**，并且带上题材术语。写「世界杯决赛补时绝杀，捧起大力神杯」，不要写「夺冠」；写「天劫雷云散开，三界修士齐跪，尊你为道尊」，不要写「飞升成功」。
- 用户任一题给自由文本，以用户为准。
- **跳过例外**：用户明确说「你直接写」「不用问了」，或主题本身已经把四要素都写清楚了 → 直接用题材卡默认值产出，并在开头一行说明你采用的设定。

### 第 3 步 · 写剧本

1. 读 `references/pov-narrative-engine.md`，按「五幕爽点曲线」铺场、控节奏、设卡点。
2. 读 `references/pov-shot-design.md`，为每一幕选好镜头策略。**每条 `△` 都是分镜，不是小说句**——按「看的方式——看到什么——正在发生什么」写，必须能答出"镜头在哪、朝哪、怎么动"。
3. 读 `references/toonflow-format.md`，逐行严格遵守格式与 `△` 行写法。
4. 过一遍第 4 步自检清单再交付。

### 第 4 步 · 自检清单（逐条核对，不过关就改）

- [ ] 全程第一人称 POV，**主角绝不出正脸**（只能用：手、脚、影子、镜中虚影、遮挡；背影镜全片 ≤2 次）
- [ ] 每场都有 `[音效：…]`，听觉先行
- [ ] 他人台词全部看向镜头、对「你」说
- [ ] 全片台词 ≤ 12 句，单句 ≤ 15 字
- [ ] 五幕完整：被轻视 → 伏笔 → 反转 → 集体崇拜 → 高光定格
- [ ] 至少 3 处 `△ 卡点：`（反转 / 跪拜起势 / 金句落点）
- [ ] 格式零偏差：`### 场1-X`、`时间 内/外 地点`、`△ `、`角色（情绪，语气）：`
- [ ] 结尾有定格 + 金句旁白或三行字幕
- [ ] 剧本正文里没有混入解释、标题之外的说明文字

**分镜设计（POV 专属，见 `references/pov-shot-design.md`）**

- [ ] **每条 `△` 都能答出"镜头在哪、朝哪、怎么动"**——不是小说句
- [ ] 三类镜配比约为 A 主观镜 80% / B 身体镜（手·脚入画）15% / C 背影抽离镜 ≤2 次
- [ ] 五幕运镜策略到位，**反转那一镜有"骤稳"**（从手持晃动骤然变稳）
- [ ] 对手角色有「轻蔑 → 惊愕 → 仰望」三次看向镜头的眼神
- [ ] 用了至少两种「主角替身」：手 / 脚 / 影子 / 他人视线与称呼 / 画外呼吸
- [ ] 无过肩镜、无正反打、无来源不明的光、不越轴；相邻两镜之间有可解释的连接（信息·动作·空间·视觉·声音·情绪 至少一项）

**自动自检（推荐，写完剧本后立刻跑）**

```bash
python <本技能目录>/scripts/check_pov_script.py "{工作目录}/pov剧本/{标题}.md"
```

确定性地检查：场次编号连续性、每场必备元素（场景行/人物行/音效）、台词句数与单句长度上限、卡点数量、三类镜配比、主角是否出镜（正脸/回头/过肩/正反打）、A·B·C 镜统计、主角替身种类。出现 `[FAIL]` 必须改到通过再交付；`[WARN]` 逐条判断是否需要改。

### 第 5 步 · 交付

1. 回复中给出**完整剧本正文**——它就是最终成品，不要再套一层解说或大纲。
2. 同时写入 `{当前工作目录}/pov剧本/{标题}.md`。
3. 附一份「AI 出片提示词包」：3-5 条可直接复用的 POV 画面提示词（套用下文「POV 电影感公式」）+ 一句统一画风描述。
4. **按需**附「POV 分镜设计表」（Markdown 表：场次 / 镜号 / 三类镜 / 景别 / 运镜 / 视向 / 声音 / 设计意图）。用户说"要分镜表""给剧组用""喂给视频工具"时默认附上；否则附在正文之后作为附录，**不要插进剧本正文**。

**POV 电影感公式**（每条提示词都要凑齐五个模块）：
`第一人称主观视角(POV) + 核心手部动作或视线主体 + 情感物细节与材质 + 生活化环境与光影 + 电影质感参数`

## 硬性规则

- 输出语言：中文。
- 主角在剧本中以「我」出现；只能用**手、手臂、鞋、影子、镜中虚影**表现，**绝不写主角正脸**。
- 主角台词近乎为零；情绪交给 `旁白（内心）` + 他人反应承担。
- 不使用 emoji；不写分镜表格、不写导演阐述混进剧本正文。
- 篇幅换算：30s ≈ 4-5 场 / 8-10 个 `△`；60s ≈ 6-8 场 / 12-16 个 `△`；90s ≈ 8-10 场 / 18-24 个 `△`。**默认 60s**。

## 分镜设计：本技能怎么保证"有设计感"

通用分镜的底层假设是"摄影机在外部观察演员"，POV 的假设是"摄影机就是主角本人"，所以很多铁律必须倒过来用（详见 `references/pov-shot-design.md` 第零节）。本技能的硬约束：

1. **每条 `△` 都是分镜**——句式固定为 `{看的方式}——{看到什么}{正在发生什么}`，句首用镜型词表。
2. **三类镜配比**——A 主观镜 ≈80% ｜ B 身体镜（手/脚入画）≈15% ｜ C 背影抽离镜 ≤2 次。
3. **运镜必须有动机**（=主角注意力的变化），并按五幕分配策略；反转那一镜固定用「骤稳」。
4. **主角零正脸**，靠五种替身（手 / 脚 / 影子 / 他人视线与称呼 / 画外呼吸）维持"我在场"。
5. **他人必须看镜头**，每个对手角色设计「轻蔑 → 惊愕 → 仰望」三次眼神。

本技能的分镜体系已把 `minimax-h3-storyboard-director`（镜头语言目录、画面连续性）与 `qiushi-ai-script-director`（镜头组接与视听判断）的可迁移部分**改写为第一人称版本**，不再依赖这两个技能。需要更细的词表时可按 `pov-shot-design.md` 文末附录去翻原文，但凡涉及"看镜头/正反打/过肩镜"的条款一律按该文件第零节反转。
