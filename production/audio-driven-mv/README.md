# Toonflow 音频驱动 MV Skill

将已经录好的歌曲按片段送入 MiniMax H3，默认使用音乐数字人音频驱动工作流生成角色对口型 MV，再导入 Toonflow 无限画布。可先用 Blender 制作白模参考视频，验证镜头和走位。重点保留原唱和原伴奏，后期只裁尾。

这是制作流程与本地辅助脚本，**不是离线视频模型，也不包含 Toonflow 或 H3 服务**。换电脑可以复现流程；模型输出具有随机性，不保证逐像素一致或一次生成口型完全正确。

## 安装

1. 在另一台电脑安装并启动支持无限画布 MCP 与 RunningHub H3 节点的 Toonflow；配置自己的 RunningHub 凭证，确认所选工作流支持一图加实际歌曲音频驱动（当前为 h3DigitalHuman）。
2. 安装 Bun、FFmpeg（包括 ffprobe），确保 `bun --version`、`ffmpeg -version`、`ffprobe -version` 可运行。图像参考生成需连接自己的图像工具。
3. 将本文件所在的整个目录复制到 `~/.codex/skills/audioDrivenMv/`，保留标准入口 `SKILL.md`；重新启动或刷新 Codex 的技能发现。其他 Agent 可读取同一 SKILL.md，但需有等价文件、图像和 Toonflow MCP 能力。
4. 在 Toonflow 中打开目标项目及画布，启用 MCP。通过本机设置或应用显示找到当前 MCP URL、运行时文件和授权方式；不要沿用其他电脑的端口、token 或 connectionId。
5. 如需白模，另行安装 Blender 并连接自己的 Blender MCP，确认可查询场景、执行 Python、保存工程和渲染。没有 MCP 时可通过 Blender 脚本或后台命令执行；仅制作图像与 H3 成片可跳过 Blender。

## 使用示例

```text
请使用 audio-driven-mv 技能，在当前 Toonflow 项目制作第1至3段。
角色图、场景图、分段WAV和歌词放在我指定的素材目录。
9:16，每个片段一个镜头，角色不看镜头，专注深情。
原唱和伴奏在H3生成时直接复用，后期只裁尾。
先把不确定唱词交给我核准，每段生成一版，保留原文件。
```

建议目录（名称可自定，不依赖特定盘符）：

```text
mvProject/
  character.png
  studio.png
  street.png
  lyrics.txt
  segmentOne/
    audio.wav
    frame.png
    prompt.md
    native.mp4
    clip.mp4
```

先核准实际唱词，再生成参考图、导入画布、检查引用、提交 H3、查询原任务、裁尾、回填和人工复核。完整步骤在 SKILL.md；当前 Toonflow 接口操作见 references/toonflowWorkflow.md。

## 使用白模参考视频的流程

以下视频参考连线仅适用于支持视频输入的全能参考路线；默认数字人仍只接最终构图图和实际歌曲音频。

适合先确认摄影机、站位和走位，再消耗视频生成用量。简单面部特写可按用户选择直接跳过。

1. 分析人物数量与关系、场景结构、关键动作、景别、机位、时长，输出简短搭建计划。确认人物纯色标记及动作时间轴后再搭建。
2. 根据定妆和场景资产制作分镜参考图；在 Blender 用低精度人形或基础几何体还原站位、尺度和镜头，不制作五官、服装、毛发或口型。
3. 保留地面、墙体、门窗、台阶、桌椅和影响走位的道具。按时间轴用简单关键帧表现姿势、路径和摄影机运动。
4. 采用低成本预览渲染，竖屏建议 720×1280、24或30fps，时长跟随该段 WAV。先检查首、中、末帧及转折帧，再导出 MP4。
5. 将 .blend、重建脚本、预演 MP4、分镜图及原 WAV 保存在项目资产目录。数字人只连接最终构图图与原 WAV；确需把预演视频送入模型时，明确改用支持视频输入的全能参考工作流并核对授权。
6. H3 中角色图负责身份和最终画风，白模视频只负责构图、动作路径及运镜，独立 WAV 是唯一最终音轨。白模形体与纯色不能迁移成成片外观；白模自带音轨不参与最终声音。
7. 检查编译后的图、视频、音频引用编号，再提交单段生成，完成后保留 H3 原生音轨并按 WAV 长度裁尾。

可直接向 Agent 提出：

```text
本段先做 Blender 白模预演，9:16。
先给出人物关系、场景、动作、景别、机位和时长的简短计划，
确认人物配色与时间轴后再搭建。人物用纯色低精度几何体，
不做五官或服装，场景只留影响走位的结构。
导出可编辑 blend、重建脚本和预演 MP4，导入 Toonflow 并连线。
H3 只参考白模的运动和镜头，最终外观用角色图，音轨只复用原 WAV。
```

具体搭建、导出命令和 H3 引用示例见 [Blender 白模预演工作流](references/blenderPrevis.md)。本包提供工作流文档；重建脚本须由 Agent 按当前分镜生成，不含绑定某个旧镜头的通用搭景脚本。

## 本地工具

### 调用现有 Toonflow MCP

将 JSON-RPC params 写到本机 JSON 文件，避免 shell 转义错误。例如查询连接：

```json
{"name":"getAppState","arguments":{}}
```

```powershell
bun scripts/mcpCall.ts --runtime "本机运行时文件.json" --method tools/call --params "请求.json" --out "响应.json"
```

`--runtime` 文件需包含 Toonflow 当前提供的 `{ "url": "http://localhost:端口/mcp", "token": "本机令牌" }`。令牌只在本机读取，不写入 Skill。URL 路径以实际应用为准。响应可能包含项目路径，上传前检查。若其他版本通过内置连接器直接调用，不必使用该脚本。

### 只裁尾，保留模型原生音轨

```powershell
bun scripts/trimToAudio.ts --video "native.mp4" --audio "audio.wav" --out "clip.mp4"
```

脚本读取 WAV 时长与视频帧率，裁剪视频及其自身音轨，不把 WAV 混入输出。画面结束于不超过参考长度的最后完整帧，音频按参考长度裁剪；AAC 编码及容器显示可有毫秒舍入。输出已存在时拒绝覆盖。

模式选择和官方方法见 [references/workflowSelection.md](references/workflowSelection.md)。

## 经验与边界

- 歌曲 MV 默认使用音乐数字人和普通动作正文；`<d>` 逐字唱词只适用于支持该格式的全能参考等路径，不能强加给数字人。文件名不能替代人工核准。
- `fully_copy` 是全能参考中的完整音轨复制意图，不是音色复制或硬保证；位置前后与中英文、六段式的独立影响尚未验证。先确认工作流，再核查返回音轨及画面口型。
- 单段提示词不要写“从街道切到录音棚”；否则可能开场闪外景或在行走中变场。每段只写本段地点，硬切交给剪辑。
- 外景路径要远离墙、门窗和台阶；镜头平行跟随。无法仅靠提示词保证无穿墙，仍需看片。
- 本地“文件正在使用”可能只影响状态保存。已有上游 taskId 必须恢复原任务，不能重复付费生成。
- 不默认添加字幕、白模、外部音乐、复杂音频识别或自动重试。按用户当前阶段制作。

## GitHub 与迁移

只上传本 Skill 目录内的文本和脚本。不要上传 MCP 运行时令牌、settings.json、任务原始响应、歌曲、角色素材或生成视频，除非你已另行决定且有相应权限。此包不含这些内容，也不绑定本机盘符。

若需把 **MV 项目** 一起迁移，另行复制 Toonflow 画布 JSON 与其引用的整个 assets 目录，在新电脑选择该目录并重新建立项目连接。仅复制 Skill 不会携带现有画布和素材。H3 工作流、音频参考端口、模型配置、MCP 参数可能随版本变动，迁移后先做一段小样验证。

上传 GitHub 不由此 Skill 自动执行；在拟上传仓库中选择自己的许可证及仓库可见性。
