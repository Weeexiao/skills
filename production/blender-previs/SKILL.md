# Blender 白模预演

输出是**镜头验证用的低精度动画**，不是最终角色建模，也不是口型动画。它只回答"这个镜头物理上成不成立"。

## 开始前

1. 取得角色资产、场景图、分镜参考图、原音频（如有）及已确认的镜头描述。
2. 问清当前是**只做预演**，还是预演通过后授权生成付费成片。制作白模本身不自动扩大付费生成范围。
3. 用户明确不要白模时直接跳过，走"参考图 + 原音频"的路线。

## 1. 分析与确认

先输出简短搭建计划，不要直接开搭：

| 项目 | 明确内容 |
| --- | --- |
| 人物 | 数量、关系、每人的纯色标记，全片保持一致 |
| 空间 | 地面尺度、墙门窗、台阶、桌椅及重要障碍物 |
| 动作 | 起始姿势、关键姿势、移动方向、路径与停顿 |
| 镜头 | 景别、焦段或视角、机位、朝向、运镜、主体画面位置 |
| 时间轴 | 音频时长、动作转折时点、摄影机运动起止 |

确认人物配色与时间轴后再制作；已有明确确认不重复询问。动作时点只是预排时标注，**不能声称已逐字或逐拍校准**。每段一个连续镜头，只描述本段场景。

## 2. 从参考图搭建

先制作或读取定妆、场景与当前镜头参考图，再还原三维站位、层次、距离与构图。记录坐标约定（例如 Z 向上、主角朝 -Y、镜头在 -Y），**不要复制旧项目的绝对坐标**。

- 人物用球、胶囊、圆柱等低精度几何体拼成，可加简单轮廓标记区分身份；不做五官、服装、毛发和写实细节。
- 人物或阵营用不同纯色区分，"白模"不要求所有物体同白。场景用灰白体块，设备用深灰。
- 只保留影响遮挡、走位或构图的物体。桌子、话筒、防喷罩、墙、门窗、台阶简化为基础几何体。
- 话筒中心对齐角色嘴部估计高度，防喷罩避开脸部轮廓；**不要默认成人话筒高度**。
- 外景要有真实可行走的地面和墙体边界；行走路径平行墙面并留距离，摄影机不穿墙、窗或角色。

## 3. 关键帧与机位

只做必要的姿势变化、位移、朝向和摄影机关键帧；省略复杂表演、步态模拟、布料、毛发及物理模拟。人物没有面部，**不能用它验证闭眼、皱眉或嘴型**。

设音频时长为 `D`，帧率为 `F`：

- `frameStart = 1`，`frameEnd = ceil(D * F)`
- 把 `t` 秒事件映射为 `1 + round(t * F)`，并夹到范围内

整帧取整使预演可能略长于音频；**记录真实时长，不拉伸原音频**。

路径匀速跟拍适合 LINEAR；停下、抬手及缓推用受控 BEZIER。检查曲线是否过冲导致人物撞墙或摄影机穿模。摄影机保持指定方向，不因自动跟踪出现意外绕拍；必要时用 Empty 作为稳定注视目标。

**每段独立场景或工程**；保存前检查场景名，避免清空用户已有工程。在独立场景内搭建，不要直接重置整个 Blender 文件。

## 4. 预览、保存与渲染

优先 Workbench 或低成本 Eevee，材质用纯色和简单工作室灯光，不做高精度渲染。建议竖屏 720×1280、24 或 30fps，沿用当前项目要求。

先渲染首、中、末及关键转折帧，检查景别、主体大小、站位、遮挡、人物与话筒高度、路径及摄影机边界；通过后再渲染全段。

保存 `previs.blend` 与按当前镜头编写的 `buildPrevis.py`。脚本通过参数或配置接收输出目录，**不绑定旧电脑盘符**。Blender 内用 bpy Python 是其原生 API，此步不用 TypeScript 替代。

后台重建（脚本需自行实现 `--output` 参数）：

```powershell
blender --background --python buildPrevis.py -- --output "项目目录/segmentOne"
```

为适配 Blender 不同版本，**优先渲染 PNG 帧序列，再用 FFmpeg 编码**，避免依赖特定版本的视频编码选项：

```powershell
ffmpeg -framerate 30 -start_number 1 -i "frames/frame%04d.png" -c:v libx264 -crf 20 -pix_fmt yuv420p -movflags +faststart previsSilent.mp4
```

帧率和编号与实际渲染一致。可另存一份带原音频的审片版：

```powershell
ffmpeg -i previsSilent.mp4 -i audio.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -shortest -movflags +faststart previsReview.mp4
```

给白模审片配原音频是为了**验证时间关系**，不是给成片换轨。推荐把无声版作为 H3 运动参考；若使用带声版，必须在提示词中显式忽略其声音。检查实际流时长，不强求毫秒长度与整帧数量同时完全相等。

## 5. 作为 H3 运动参考接入

把分镜图、角色图、原音频、白模 MP4、工程和脚本复制到项目工作区，媒体用相对路径。新增视频参考后**引用序号会变化**，不能假设音频仍是原来的 `{{ref N}}`；实际映射确定后全篇统一，并校验编译结果。

H3 六段格式中的白模声明要点：

```text
{{ref N}} Graybox motion reference — Only composition, blocking, camera trajectory,
timing and coarse body gestures. Its primitive shapes, flat colors and any
soundtrack are not final appearance or audio.
```

`retention_analysis` 中白模标为 `partially_preserved`，仅保留运动与机位，并显式写 `Ignore its audio entirely.`。

- 最终角色表情、口型与原唱按独立音频执行，**不让白模的无口型固定面部覆盖演唱**。
- **禁止把白模当作最终视觉风格**，或把它的审片声音当成第二条音频源。
- 六段字段顺序与完整声明写法见 `h3-prompt-writing` 与 `minimax-h3-storyboard-director`；MV 场景的接线差异见 `production/audio-driven-mv/references/blenderPrevis.md`。

## 6. 验收与迁移

保留：搭建计划、参考图、`.blend`、重建脚本、帧序列或代表帧、预演 MP4、原音频、H3 提示词、原生输出及裁尾版。记录帧率、尺寸、参考时长、预演实际时长和引用映射。

白模只验证空间和运动；成片仍需人工检查口型、表情、不看镜头要求及场景连续性。

迁移电脑时**复制工程和资产**，不仅复制预演 MP4；仅上传技能不能携带这些工程。仓库不包含个人 Blender 工程、歌曲或视频。

## 调用哪个 Blender 技能

本技能只管白模这一类工作。搭几何、布机位、打关键帧、出渲染分别由 DSH 内置 Blender 技能的对应模块承担，完整路由与"协作前如何确认这些技能到位"见 `tooling/dsh-orchestrator/references/blenderSkills.md`。

最低必需组合：

| 阶段 | 模块 |
| --- | --- |
| 简化几何、体块、障碍物 | `blender-modeling` |
| 机位、焦段、跟拍、注视 | `blender-cameras` |
| 位移与摄影机关键帧 | `blender-animation` |
| PNG 序列与采样设置 | `blender-rendering` |

## 依赖

Blender 可执行文件（`blender` 在 PATH 中，或配置到 DSH 的 `blenderExecutable`）+ FFmpeg。**Blender 本体是硬依赖**：不可用时本技能无法产出预演视频，应直接报告缺项，不要用文字计划替代。
