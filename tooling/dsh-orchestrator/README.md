# DSH Orchestrator

让 Codex 指挥 DeepSeek Harness（DSH）执行任务：Codex 负责判断、必要的方案设计和最终验收，DSH 负责具体执行。目标是在满足任务质量要求的前提下，减少 Codex 用量。

## 快速启用

1. 在电脑上打开 DSH 桌面版，配置好 DeepSeek Flash，并确认可以正常对话。
2. 将本仓库放到 Codex 技能目录，默认位置为 `~/.codex/skills/dsh-orchestrator/`。如果设置了 `CODEX_HOME`，则放到其 `skills/dsh-orchestrator/` 下。
3. 确认目录中直接包含 `SKILL.md`，并让 Codex 重新发现技能，必要时新开对话。
4. 确认 Codex 环境提供桌面控制工具，并具备所需系统权限。技能本身不提供桌面控制工具，也不会自动安装 MCP。
5. 对 Codex 发送下面的指令。

```text
使用 $dsh-orchestrator，连接我已经打开的 DSH 桌面，沿用当前 Flash，
在当前项目新建协作会话，进行一次不修改文件的连通验证。
后续明确任务直接委派，复杂任务先由你确定方案再委派，由你验收。
目标是在满足质量要求的前提下节省 Codex 用量。
```

成功标准：DSH 桌面中能看到 Codex 的任务指派和实际回复。换电脑时只迁移技能，不复制账户凭据或整份机器配置。

## 哪些任务交给 DSH

| 处理方式 | 适用情况 |
| --- | --- |
| 直接交给 DSH | 规格清楚、可以隔离执行、容易验收的建模、批量转换、资产整理、按既有模式修改代码 |
| Codex 先分析，再交给 DSH | 根因不明、跨模块、涉及方案选择的复杂任务；先明确实施路径、修改范围、边界和验收标准 |
| Codex 直接完成 | 很小的修改、关键决策和最终验收，或委派成本高于直接执行的任务 |

DSH 的“已完成”报告不等于验收通过。Codex 需要检查实际产物、关键变更及必要的类型检查、构建或画面效果。派发时会传递仓库约束，不允许覆盖用户已有改动或擅自扩大任务范围。

## 当前连接方式与限制

2026-10-17 已验证：通过 macOS DSH 0.2.1-rc.1 桌面界面派发并获取回复，沿用界面当前的 DeepSeek-V4.1-Flash，用户可见会话记录。

HTTP MCP 桥直连该桌面实例仍存在认证兼容问题，返回 401，尚未接通。独立运行的 DSH MCP 桥与桌面实例不同，其任务记录不会因此自动显示在桌面。

桌面方式需要 DSH 保持运行，并受界面状态和用户同时操作影响；不能承诺 Codex 对话结束后继续后台调度或自动唤醒。
