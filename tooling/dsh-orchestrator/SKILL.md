# DSH 协作

目标是减少 Codex 的总工作量并保持质量，不是增加委派次数。不承诺固定节省比例。

## 分流：按顺序选择第一条成立的路径

1. 本机现有工具能直接完成：直接调用。读文件、搜索、单条命令、小修改不交给 DSH 模型，不写派单文案。
2. 需要 DSH 独有工具：通过已验证的桌面 MCP 的 `dsh_tool_call` 直接执行，不发 `session_prompt`。先按需查询工具参数，不加载全部 schema。保留宿主认证、工具授权和审批。
3. 有一整块可独立闭环的工作：才交 DSH 模型，例如多文件实现、建模全流程、需自主修正的批处理。简单可描述任务直接交付目标；复杂任务先读关键调用链，明确选定方案与边界，避免让双方重复分析或编写实现。
4. 预计派单、等待与验收比直接完成更费力：由 Codex 完成，不为使用 DSH 而使用 DSH。

已授权范围内自主执行，无需用户人工转发。沿用用户配置的模型，不硬编码 Flash，不擅自切换收费来源或扩大发布权限。

## 协作前：技能到位检查

派单前先确认目标能力在本机真的存在，**不假定 DSH 一定能做**。技能注册、运行时可用、路径可写是三件独立的事，任何一项不成立就先补齐或改路线，不要把任务交出去再说。

- 技能是否注册：在本会话技能目录按名加载，抽查代表技能。
- 运行时是否可用：要 Blender 就查 `blender_status`，`available` 必须为真且版本真实（不是 `spawn blender ENOENT`）；要命令就跑一次最小调用。
- 产物路径是否可写：确认隔离目录存在。

Blender 类的完整检查清单、30 个内置技能的用途速查与"什么情况调用哪个"的路由表见 [Blender 技能路由](references/blenderSkills.md)。白模预演流程本身在 `production/blender-previs/`。

## 连接与调用

用户要求部署本技能、首次连接、失联或换电脑时，执行 [连接说明](references/connection.md) 的完整流程：先检测插件与运行状态，缺少则从固定来源下载，已有则修复/复用注册，安装客户端后验证实际工具和桌面记录；不要停在给用户一份操作建议。优先已验证的桌面接口，桌面 UI 仅作回退，不反复截图轮询。独立 SDK 实例不等于桌面会话。

本技能包含 `scripts/dshControl.ts`：`list [关键词]` 只列名称与描述，`describe 工具名` 按需取参数，`call 工具名 'JSON'` 执行。命令入口是标准 MCP 客户端，不是另一层模型。只查询需要的接口；结果优先通过原工具的 limit/分页限制，不反复拉全量历史。

2026-10-20：已审计选择 dsh-as-mcp 0.1.5 作为宿主插件；本机新桌面链路仍待加载插件后验证。不能将旧桥 401、CLI 编写完成或静态检查通过描述成桌面已经连通。

## 模型委派

默认一条短指令即可，按实际需要补充：

> 在【隔离目录】完成【目标】。遵守目录内 AGENTS.md；仅改【范围】，注意【关键约束/复杂任务选定方案】。运行【必要验证】，返回结果、产物路径与未解决问题，不复述过程。

不要求固定八字段，不复制完整聊天或整个仓库，不先由 Codex 写完实现再让 DSH 誊写。代码任务使用隔离工作区，保留用户未提交修改；媒体任务用独立输出目录。禁止新增测试文件的项目必须显式传递此限制。

优先异步 `session_prompt(wait:false)`，保存 session ID，按状态退避等待；终态只读取最后必要回复。不要逐工具复核或频繁轮询。超时后先查原任务，不重复提交。任务相关步骤复用同一会话，无关任务另开。不要承诺父对话结束后能自动唤醒。

## 验收

DSH 自报成功不代替实际产物检查。完成后做一次与风险匹配的验收：关键 diff 与已有检查、实际渲染、数量与代表样本。发现明确失败才定向补查；不重复整套执行过程。修正一次仍失败或协调成本已高于直接修复，Codex 接手。

报告实际完成、验证与限制，不把 partial、失败或未连接包装成成功。不凭猜测报告节省 token 百分比。
