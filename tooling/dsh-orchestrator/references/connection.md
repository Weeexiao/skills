# 连接、部署与换电脑

## 最快路径：已有 DSH 桌面

1. 在新电脑安装并打开 DSH，用户自行登录或配置模型，确认可以正常对话。沿用用户选择的 Flash，不从旧电脑复制凭据。无需仅为委派重新搭建独立 DSH 实例。
2. 将本技能仓库克隆到该电脑 Codex 的 skills 目录，文件夹中直接包含 SKILL.md；默认目录为 ~/.codex/skills/dsh-orchestrator，若设置 CODEX_HOME 则使用其 skills 子目录。已有同名目录先检查来源和本地修改，不能直接覆盖。
3. 在目标 Codex 客户端确认技能已发现，必要时新开对话。安装技能本身不会安装桌面控制工具、MCP 或模型，也不会赋予系统权限。
4. 确认当前 Codex 环境实际具备桌面控制工具；macOS 还需已授权所需的辅助功能/屏幕访问。先用可用工具发现并选中 DSH，再按工具返回文档操作；不能照抄旧机器的元素序号、窗口 ID 或端口。
5. 在 DSH 选择实际项目工作区，新建独立会话，核对界面上的模型。派发一条不读写业务文件的短任务：“这是 Codex 桌面协作连通验证，不调用工具、不修改文件，请回复‘协作已连通’。”
6. 看到回复完成后，核对用户在桌面能看到同一指派和回复，保存会话标题。仅验证能打开窗口不算连通；仅独立进程返回结果也不算桌面可见。

完成后记录：系统/DSH 版本、连接方式、项目目录、模型显示名称、会话标题，以及尚未验证的能力。桌面必须保持运行；界面操作会受窗口状态和用户同时操作影响。连接中断后先恢复并查询原任务。

可向新电脑上的 Codex 发送：

> 使用 $dsh-orchestrator，连接我已经打开的 DSH 桌面，沿用当前 Flash，在当前项目新建协作会话并进行一次不修改文件的连通验证。后续明确任务直接委派，复杂任务先由你确定方案再委派，你负责验收；以节省 Codex 用量并满足质量要求为目标。

## 可选路径：MCP/API

只有桌面 UI 不可用或实际吞吐需要更稳定的接口时再配置；不要默认要求用户安装多个桥。先查当前工具目录、已配置 MCP 与官方版本资料，优先复用已有兼容连接。不同桥的协议和任务工具不可混用。

曾检查的第三方项目（均非 DSH 官方认证承诺）：

- [knottttt/codex-dsh-bridge](https://github.com/knottttt/codex-dsh-bridge)：通过现有 WebUI 本机 RPC 建会话、派发和读取消息，包含 companion 设置插件。必须核对目标桌面版本、认证和实际 profile。2026-10-17 对桌面 0.2.1-rc.1 直接连接返回 HTTP 401，不能照搬无认证 WebUI 示例宣称兼容。
- [HazenSun/dsh-codex-bridge](https://github.com/HazenSun/dsh-codex-bridge)：本地已验证的是独立 Home/Profile 的任务桥，不是正在运行的桌面会话。不要把共享目录、复制登录文件或指定端口当作桌面复用成功。

安装前阅读所选版本的原始 README、依赖和实际脚本；确认来源、版本兼容与授权边界。备份将修改的配置，仅修改所需项，保留原连接作为可回退选项。不得降低认证、开放公网端口、输出 key 或擅自换付费模型。桌面 profile 不一定叫 web；需要根据真实启动配置确定。

不要把旧电脑的端口、用户名路径、Home/Profile、token 和 config.toml 整份同步到新机。配置应由当前电脑发现或由用户设置。新增 MCP 是否需新会话加载，以实际客户端说明和工具可见性为准；当前会话未加载时明确说明。

验证链路：服务可达 → 合法认证 → 读取会话 → 新建独立会话 → 短任务完成 → 桌面显示同一记录。任一步失败，仅报告实际通过的步骤，回退桌面 UI 或说明具体阻碍。不要重复提交验证任务。

## 建模能力单独验证

普通对话连通不代表 Blender 可用。检查本机 Blender 路径/版本，再验证现成 DSH 建模工具或 shell 调用能力。有插件需求时另查其版本兼容，不能默认安装 dsh-blender 就兼容所有桌面版本。交付 .blend、预览图和关键尺寸/材质说明，并由 Codex 实际打开或读取工程验证；不以一段文字回复代替建模交付。

## 上传 GitHub

只上传本技能的 SKILL.md 和 references；不要包含 .dsh、会话日志、凭据、项目业务文件或个人绝对路径配置。用户指定仓库后再添加远程和推送。换电脑使用该仓库 URL 安装；如果要用技能安装器，先检查目标 Codex 是否提供该能力，再按其文档操作。
