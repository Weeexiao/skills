# 输出内容参考

先按 [交付模式路由](delivery-mode-router.md) 确认模式，再决定是否交付 Excel。B、C、D 模式交付 Excel；A 模式只交付故事板总览与逐格说明。工作簿结构、字段和视觉检查要求见 [Excel 交付规范](excel-delivery.md)。

## A. 从想法到分镜

1. **创作判断**：一句话说明片子要让谁感受到什么；列出已知条件与必要假设。
2. **秋拾方法依据（必有）**：用一张简表把“内置方法编号 → 适用条件与具体做法 → 本项目改写 → 内置案例证据”说清楚。至少 2 条实际使用的方法；案例证据必须来自内置方法库的真实条目。用户额外上传参考材料时，才补充其镜头级证据。
3. **结构方案**：用 3–5 段说明开场、推进、核心看点、结尾各承担什么任务；各段标注对应的方法依据编号。
4. **逐镜分镜（必有）**：B、C 模式写入 Excel 的“分镜脚本”工作表。每一镜一行，写清拍摄、剪辑、时长、声音与方法依据；只有 C 模式或用户明确要求“带图”时，才在每行嵌入原创草图。
5. **执行清单**：写入 Excel 的“拍摄清单”工作表，标出必拍镜头、可选镜头、需提前准备的物件/人物，以及素材不足时的替代拍法。

片长很短时可写成“镜头组”而非逐个镜头；剧情、宣传片或需要现场拍摄执行的项目，优先给逐镜分镜。

## B. 脚本优化

1. **秋拾方法依据（必有）**：按 A 的要求，以内置方法的适用条件和具体做法解释调整建议的依据；用户上传参考材料时，再补充其镜头证据。
2. **保留项**：指出原稿已经有效的主题、画面、人物关系或情绪。
3. **核心问题**：只指出会影响成片的关键问题，例如开场信息不清、结构重复、情绪跳跃、文案与画面重复、镜头条件无法实现。
4. **调整思路**：说明结构怎样变化、引用哪条方法依据，以及每个变化解决什么。
5. **修改稿（必有）**：将调整后的逐镜脚本写入 Excel；每一镜一行并标注方法依据编号。只有 C 模式或用户明确要求“带图”时，才嵌入对应原创草图。
6. **下一步**：列出 2–4 项用户下一次就能完成的准备或拍摄动作。

没有把握的具体秒数、镜头参数、音乐版权状态不能假定为已确定。

## C. 单场景 6 / 9 宫格故事板

1. **场景判断（必有）**：说明用途（实拍 / AI 生成）、场景任务、开始状态、关键变化、结果或下一场出口，以及选择 6 格或 9 格的理由。信息不足时，只列必要假设。
2. **本场景秋拾判断依据（必有）**：至少 2 条真实适用的方法。每条包含方法编号、适用条件、具体做法、本场景改写和内置案例证据。资料库没有直接对应时，另列“原创补充设计”，不能伪造方法依据。
3. **故事板总览（必有）**：按顺序合成为 3×2 或 3×3 的黑白 / 低饱和原创手绘草图总览。总览不生成文字、Logo、水印或品牌；每一格必须承担不同的信息、动作或情绪任务。
4. **逐格说明（必有）**：每格写入镜号、建议时长、景别/构图、人物或物件位置、动作、镜头任务、剪辑/声音连接和方法依据。剪辑栏写实际切法与切点，不放 `QS-` 编号。
5. **用途附加项（必有）**：实拍版逐格给出可拍性与低成本替代；AI 生成版逐格给出图片提示词和人物、服装、场景、光线、道具的连续性锚点。

**A｜故事板预览**：正式交付是 PNG 故事板总览与逐格说明，不生成 Excel。若平台无法生成图片，仍交付明确的 3×2 / 3×3 排列、逐格构图说明和图片提示词。

**C｜完整制作包**：在“故事板总览”工作表放总览图和判断，在“分镜脚本”工作表逐格一行嵌入对应原创草图；可额外输出 PNG 总览图。B 模式不因用户只要表格而生成故事板。
