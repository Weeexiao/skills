# 抖音与小红书内容开头参考层

本文件只提供公开可核对的平台内容规律与开头判断方向，作为创作时的补充参考；它不是“爆款公式”，也不保证播放量。生成时始终先遵循用户的真实题材、拍摄条件、基础镜头组接与秋拾方法库，不复制其他创作者的文案、人物、镜头顺序或辨识度画面。

## 使用范围

当用户明确发布平台为抖音或小红书，或提出“开头留人、首屏、停留、爆款结构、搜索流量”等目标时读取本文件。先选一个与题材匹配的平台开头策略，再用秋拾方法把它变成可拍的镜头组；没有必要时，不为追求“爆款”硬塞反转、快切或夸张话术。

如果当前平台具备网络检索能力，且用户要求追踪当下热点，可在生成前额外检索用户题材下近期公开案例；检索不可用时，直接使用本文件完成任务，不能要求用户配置外部案例目录或因此中断创作。

## 抖音：首屏更快交代“为什么要继续看”

公开可查的抖音创作案例常将前 3–5 秒作为开场钩子区间。可从下列三种方式中选择一种，且必须在后续镜头兑现：

1. **未完成动作 / 问题先行**：第一镜先给正在发生但尚未解释的动作、异常细节或结果，再补人物和原因。适用于 Vlog、剧情、体验、改造和教程。镜头上使用“动作峰值或结果局部 → 人物/空间 → 过程”的信息链，对应秋拾 QS-A02、QS-B06、QS-C01。
2. **明确收益 / 结果先给**：先给观众可感知的成品、前后差异或关键卖点，再拆过程。适用于产品、教程、探店和改造。首镜必须看得出结果，第二镜补证据或动作，避免只说“很好”却没有画面依据，对应 QS-A01、QS-A04、QS-B01。
3. **反差 / 提问先给**：用真实条件中的反差或未解问题启动，例如人物所处空间与目标不同、操作看似简单却有关键限制。画面必须同步给出反差证据，不能只靠夸张文案。后续在同一段落内回应问题，对应 QS-A02、QS-A03、QS-D04。

抖音开头镜头组的最低要求：第一帧有可识别主体或动作；前 3–5 秒至少完成“看见什么”和“为什么继续看”两件事；声音只用于加强注意点，不能替代信息。

## 小红书：先给真实场景、具体对象和可验证价值

小红书的公开创作指引持续强调内容与搜索词/人群的相关性，并会整理高热话题范式。对视频镜头的可迁移做法是：先把“谁在什么情境下遇到什么问题或得到什么体验”拍清楚，再展开过程、选择和结果；不要只做无对象的氛围蒙太奇。

1. **真实使用场景开头**：第一镜给人物、地点与正在面对的需求；第二镜给对象或选择。适用于生活方式、探店、美食、旅拍、产品和经验分享，对应 QS-A01、QS-B01、QS-B05。
2. **结果 / 细节先给，再回到过程**：先给最能验证质感、变化或体验的局部，再回到空间与过程。适用于产品、空间、美食、妆造和改造，对应 QS-B01、QS-B06、QS-C04。
3. **过程可信度开头**：先给真实准备、选择或关键动作，再用过程节点和结果建立可信度。适用于教程、记录、体验和测评，对应 QS-A04、QS-B06、QS-D01。

小红书开头镜头组的最低要求：首屏能识别对象/场景；前段能看出内容与标题承诺的关系；画面、文字和声音各补充不同信息，避免互相重复。

## 平台策略如何落进故事板或 Excel

在“项目总览”新增或写明一行：`平台首屏策略｜平台 + 选择的开头方式 + 第一帧画面 + 前 3–5 秒信息 + 声音任务 + 后续兑现位置`。

随后按以下顺序设计，而不是先堆镜头：

`平台首屏承诺 → 镜头组叙事任务 → 景别与动作链 → 相邻镜头连接 → 声音/节奏 → 秋拾方法依据`

用户只要故事板时，在“场景判断”先写首屏策略；用户要 Excel 或完整制作包时，在“项目总览”写首屏策略，并在分镜表 J 列把实际切法和切点写清。平台策略不得覆盖用户的真实条件、基础视听逻辑或秋拾方法。
